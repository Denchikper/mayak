# Устройства

## Аутентификация по `auth_token`

Каждое устройство аутентифицируется на WebSocket-сервере по `auth_token`.

- Токен генерируется автоматически при создании устройства в веб-панели и для уже
  существующих устройств при первом запуске сервера (см. лог `DB WARN` с выданным токеном).
- В карточке устройства (страница «Устройства») токен можно скопировать или перевыпустить.
- Устройство передаёт токен в сообщении `register`; при несовпадении сервер отклоняет подключение.

> После включения проверки токена действующие устройства не подключатся, пока в них не
> прошьют актуальный `auth_token`.

## Конфиг прошивки: `secrets.h`

Сетевые адреса (dev/prod IP, шлюз, WebSocket URL сервера) и `auth_token` устройства не
хранятся в `.ino`/`.cpp` — они вынесены в `secrets.h` в папке каждого скетча
(`devices/esp-receiver/sketches/esp_receiver_sketch_N/`, `devices/esp-rele/esp_rele_sketch/`).
`secrets.h` в `.gitignore` и в репозиторий не попадает; в скетче лежит только шаблон
`secrets.example.h`.

Перед прошивкой устройства:

```bash
cp secrets.example.h secrets.h
```

и заполнить `secrets.h` реальными значениями (IP устройства, WS-адрес сервера,
`DEVICE_AUTH_TOKEN` — значение `auth_token` из карточки устройства в панели). Arduino IDE
компилирует все файлы в папке скетча вместе, поэтому `secrets.h` подключается через
`#include "secrets.h"` и работает без дополнительной настройки.

## Проверка по IP

При подключении устройства сервер дополнительно сверяет `device_name` + сохранённый
в БД `ip_address` с реальным IP входящего WS-соединения
(`server/src/services/websocket/handlers/handleConnection.js`). Несовпадение логируется
как потенциальная подмена устройства.

Эта проверка работает только если backend видит **реальный IP** подключающегося устройства,
а не адрес докер-бриджа — см. [DEPLOYMENT.md](DEPLOYMENT.md#host-network-и-реальный-ip-устройств).

Прошивки и схемы устройств — в папке `devices/` в корне репозитория; datasheet модуля
WT32-ETH01 — `docs/WT32-ETH01_datasheet_V1.4.pdf`, схема БД — `docs/db_scheme.png`.
