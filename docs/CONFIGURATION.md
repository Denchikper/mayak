# Конфигурация

## Переменные окружения

Создайте корневой `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DATABASE_HOST` | `db` | Хост Postgres. `db` — сервис из `docker-compose.yaml`. Для `docker-compose.hostnet.yaml`/`docker-compose.ghcr.hostnet.yaml` укажите `127.0.0.1`, для внешней БД — её адрес |
| `DATABASE_NAME` | `system_control_alerts` | Имя БД |
| `DATABASE_USER` | `postgres` | Пользователь БД |
| `DATABASE_PASSWORD` | `postgres` | Пароль БД — обязательно смените на проде |
| `DATABASE_PORT` | `5432` | Порт Postgres |
| `SERVER_PORT` | `2255` | Порт backend (HTTP API + WebSocket) |
| `WEB_PORT` | `3000` | Порт frontend |
| `VITE_API_URL` | `/api` | Базовый путь API для фронтенда при сборке |
| `JWT_SECRET` | `change-me` | Секрет для подписи JWT — обязательно сгенерировать случайный (см. ниже) |
| `JWT_EXPIRES_IN` | `2h` | Время жизни JWT-токена |
| `WS_HEARTBEAT_DEVICES_INTERVAL` | `30000` | Интервал heartbeat-проверки устройств по WS, мс |
| `RELAY_DEVICE_ID` | `a41942b7-4f77-4b13-90d5-da88294125f1` | ID устройства-реле для системного звонка |
| `RING_CHANNEL_ID` | `6` | Канал системного звонка |
| `LOG_RETENTION_DAYS` | `30` | Сколько дней хранить записи журнала (logs), старше — удаляются автоматически |

Обязательные переменные (`JWT_SECRET`, `DATABASE_*`) проверяются при старте — без них сервер
не запустится с понятной ошибкой.

### Генерация `JWT_SECRET`

```bash
openssl rand -base64 48 | tr -d '$'
```

Символ `$` в значениях `.env` лучше исключать — Docker Compose интерпретирует `$` как
начало переменной окружения даже внутри значений и может тихо обрезать/испортить секрет
при подстановке (например `$n(...)` превратится в пустую строку вместо буквального текста).

## База данных и первичные данные

PostgreSQL входит в `docker-compose.yaml`/`docker-compose.ghcr.yaml`/`docker-compose.ghcr.hostnet.yaml`
отдельным сервисом `db` (volume `sca-db-data`), отдельная установка БД не нужна.
При старте сервер сам синхронизирует схему (`sequelize.sync`) и наполняет её идемпотентным сидом:

- дни недели (Пн–Вс);
- каналы (Пожарная/Ракетная/Воздушная/Химическая тревоги, Звонок, Учебная тревога);
- системная роль `admin` (полный доступ);
- администратор по умолчанию **`admin` / `admin`** — создаётся только если пользователей ещё нет.

> Сразу после первого входа смените пароль администратора (Настройки → Пароль).

## Роли и доступы (RBAC)

Доступ разграничивается ролями. Роль — это набор прав на **разделы** (страницы) и **блоки**
(части интерфейса). Ограничения применяются и на фронте (скрытие UI), и на бэке (проверка прав
в middleware).

- **Настройки → Роли и доступы** — создание/редактирование ролей и галочки прав.
- **Настройки → Пользователи** — создание пользователей и назначение ролей.
- Роль `admin` системная: всегда имеет полный доступ, её нельзя удалить/изменить.

Health-check без авторизации: `GET /api/ping`.
